1. EXECUTIVE SUMMARY & WORKSPACE FOUNDATION
--------------------------------------------------------------------------------
This document provides an exhaustive, forensic-grade record of the entire build,
architecture, and engineering lifecycle of the MNIME workspace from its
inception
to its final release-hardened state.

MNIME is a high-performance, privacy-first Windows desktop application that
combines
multimodal document processing (PDF merging, splitting, OCR, heuristic
bookmarking,
high-resolution image editing, and native raster printing) with an embedded,
quantized local neural language model (MNIME-Core 1.5B via llama.cpp/GGUF) for
offline semantic search, summarization, and query extraction.

Key Technologies:
  - Runtime: Python 3.12.8 (64-bit on Windows 11)
  - Graphical Interface: PyQt6 (v6.7+) with custom OpenGL-like QPainter vector
    engines
  - Document Engine: PyMuPDF (fitz 1.24+), pypdf, pdf2docx, Pillow (PIL)
  - Native Print Engine: Windows Win32 GDI API (ctypes, PrintDlgW,
    StretchDIBits)
  - Neural Engine: llama-cpp-python, sentence-transformers, FAISS vector search
  - Inter-Process Communication: Windows Named Pipes / Qt QLocalServer (single-
    instance IPC)
  - Packaging: PyInstaller 6.10+ (spec-driven)
  - Custom Installer: Self-contained PyQt6 animated particle & 5D projection
    wizard

4. COMPLETE BUILD SYSTEM SPECIFICATIONS & STEP-BY-STEP PROCESS
--------------------------------------------------------------------------------
The MNIME build system consists of a multi-tiered pipeline designed to produce
standalone, portable, and production-ready Windows binaries.

Prerequisites on Windows 11:
  - Python 3.12 (64-bit) with venv and pip.
  - Inno Setup 6 (installed to C:\Program Files (x86)\Inno Setup 6\ISCC.exe).
  - (Optional) Windows 10/11 SDK with signtool.exe for digital code signing.

Pipeline Architecture:
  Source Code (.py)
    --> Icon Generator (core/app_icon.py)
    --> PyInstaller Bundle (MNIME.spec)
    --> Output Directory (dist\MNIME\)
    --> Dual Installer Builders:
          1. Inno Setup Compiler (MNIME.iss) -> installer\MNIME_Setup.exe
          2. PyInstaller Custom Installer (MNIME_installer.spec) ->
             installer\MNIME_installer.exe

Detailed Step-by-Step Execution:

Step 1: Environment Initialization
  The script build_app.bat verifies or creates a Python virtual environment
  (.venv)
  in the workspace root:
    python -m venv .venv
    .venv\Scripts\python.exe -m pip install --upgrade pip
    .venv\Scripts\pip.exe install -r requirements.txt
    .venv\Scripts\pip.exe install pyinstaller pillow pymupdf pypdf pdf2docx

Step 2: Procedural Icon Generation
  Prior to compiling, the script invokes:
    .venv\Scripts\python.exe -c "from core.app_icon import ensure_ico_file; ensure_ico_file()"
  This dynamically calculates the multi-dimensional projection and writes MN.ico
  containing multi-resolution frames (16x16, 32x32, 48x48, 64x64, 128x128,
  256x256).

Step 3: Core Application Compilation (PyInstaller Directory Mode)
  The build script purges stale artifacts and executes PyInstaller:
    rmdir /s /q "build"
    rmdir /s /q "dist"
    .venv\Scripts\pyinstaller.exe --clean --noconfirm "MNIME.spec"

  MNIME.spec configuration:
    - Entry Point: MNIME.py
    - Mode: Directory mode (COLLECT) for fast startup and reliable dynamic DLL
      loading.
    - Hidden Imports: Collects all submodules for pymupdf, pypdf, PIL, PyQt6,
      core,
      ui, llama_cpp, faiss, and sentence_transformers.
    - Excludes: Unnecessary heavyweight libraries (matplotlib, tensorflow,
      spacy).
    - Output Target: dist\MNIME\ containing MNIME.exe and _internal\ runtime.

Step 4: Standard Inno Setup Installer Generation
  If Inno Setup 6 is detected, ISCC.exe is invoked against MNIME.iss:
    "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" MNIME.iss
  - Packages the entire contents of dist\MNIME\* into an ultra64 LZMA2
    compressed
    installer at installer\MNIME_Setup.exe.
  - Registers shortcuts and Windows Add or Remove Programs metadata.

Step 5: Modern Animated Custom Installer Generation
  The script compiles custom_installer.py using MNIME_installer.spec:
    .venv\Scripts\pyinstaller.exe --clean --noconfirm "MNIME_installer.spec"
  - Mode: Single-file executable (EXE) embedding dist\MNIME as internal datas.
  - Generates installer\MNIME_installer.exe.
  - On execution, this installer displays a GPU-rendered dark glassmorphic
    window
    with flying document particles, real-time extraction progress, PowerShell-
    backed
    shortcut creation, and Windows uninstallation registry registration.

Step 6: Automated Local Deployment & Stale-Build Check (install_mnime.bat)
  Developers or users can execute install_mnime.bat for instant local
  installation:
  - Compares timestamps of core/ and ui/ source files against
    dist\MNIME\MNIME.exe.
  - If source files are newer, automatically triggers build_app.bat first.
  - Gracefully terminates running MNIME.exe processes.
  - Copies binaries to %LOCALAPPDATA%\Programs\MNIME.
  - Creates Desktop and Start Menu shortcuts.
  - Registers uninstaller in Windows Registry (HKCU).


5. ARCHITECTURAL DEEP-DIVE INTO KEY SUBSYSTEMS
--------------------------------------------------------------------------------

A. Native Windows GDI Print Engine (core/print_engine.py)
  - Problem: Standard Qt QPrinter output produced completely blank pages on
    Windows
    due to DPI coordinate mapping flaws when rasterizing PyMuPDF page pixmaps.
  - Solution: Replaced Qt print pipeline with native Win32 GDI calls via ctypes:
      * PrintDlgW: Native Windows printer selection and page range configuration
        dialog.
      * StartDocW / StartPage: Initiates Windows print spooler job.
      * StretchDIBits: Streams raw 32-bit BGRA bitmap scanlines directly to the
        printer's device context (hDC).
      * Memory Cap: Enforced MAX_RASTER_PIXELS (60,000,000 pixels / ~240 MB) and
        MAX_DPI (300 DPI) to prevent out-of-memory crashes on billboard
        printers.

B. Single-Instance IPC Architecture (core/ipc.py & ui/main_window.py)
  - Problem: Users opening multiple documents or clicking file associations
    spawned
    multiple memory-heavy instances, duplicating local model allocations.
  - Solution: Local named pipe single-instance manager using QLocalServer:
      * Server Name: "MNIME_SingleInstance_IPC_Server"
      * When a secondary instance starts, it detects the active server, packages
        CLI
        arguments via build_open_request(), transmits the payload over the local
        socket,
        and terminates immediately.
      * The primary instance receives the socket signal, parses and validates
        the payload
        via parse_open_request() (capping payload size at 256 KB and paths at
        4096 chars),
        restores/unminimizes the window, and opens the requested documents.

C. 5D Penteract Projection Engine (ui/main_window.py & custom_installer.py)
  - Architecture: Renders a 5-dimensional hypercube (penteract) projected onto a
    2D canvas via 5D rotation matrices.
  - Vertices: 32 vertices with coordinates (+-1, +-1, +-1, +-1, +-1).
  - Edges: 80 connecting edges where coordinates differ by exactly one
    component.
  - Rotation: Rotates across multiple planes (XY, XZ, XW, YV, ZV) with
    trigonometric
    transformation applied per animation frame.
  - Z-Sorting: The orbiting document file tracks 3D camera depth, scaling
    dynamically
    and rendering either under or over the wireframe to provide true depth
    illusion.

D. Content-Based Heuristic Bookmarking (core/pdf_engine.py)
  - Inspects all text spans on each PDF page via PyMuPDF.
  - Computes statistical font size distribution across the document.
  - Identifies headings (text spans with font size > 1.2x body text or bold
    styling).
  - Constructs a nested outline tree and inserts PDF bookmarks (TOC) into the
    document
    without modifying underlying text.
